## 재현 시도 — 기본 경우는 정상 동작

`nny_sim` 폴더에서 `test_new_mechanics.make`로 두 카드를 한 번의 효과(예: 패 2장 버리기 같은 단일
코스트/효과)로 동시에 묘지로 보내 보았다:
```python
g = make('소원의 분수', '소원의 분수')
coin = on_field(g, '코인 - 희생의 펜던트', 0)
hero = card(g, '영웅의 조건 - 용기', 0, 'hand')
g.events = []
g.send_grave(coin); g.send_grave(hero)   # 같은 처리 안에서 둘 다 묘지로(한 번의 do_move가 하는 일과 동일)
g.triggers()
```
→ `choose_triggers`에 **두 카드의 [유언]이 한 번에 같은 cands 리스트로** 들어온다
(`[('코인 - 희생의 펜던트', 2), ('영웅의 조건 - 용기', 2)]`) — 세창이 말한 "이전에 고친" 일반
순서 선택 메커니즘(`Game.collect`가 한 플레이어의 모든 후보를 모아 `ai.choose_triggers`에 한 번에
넘기는 것)이 **이 기본 경우에는 정상 작동**한다.

## 막힌 점

soltop_의 제보에는 실제로 어떤 효과가 "동시에 묘지로 보냈는지"(코스트로 같이 버렸는지, 서로 다른
체인 링크의 각기 다른 처리 단계에서 각각 묘지로 갔는지, 상대 효과로 인한 것인지 등)가 없어서,
위의 "가장 단순한 경우"만으로는 soltop_·세창이 보고 있는 실패를 재현하지 못했다. 세창의 "다른
데에서 다시 터지네"라는 말은 **단순 경우가 아닌 특정 상황**(코스트 단계와 처리 단계가 갈리는 경우,
체인이 걸린 상태, 상대 턴 등)을 가리키는 것으로 보이는데 추측으로 짚어 엔진 순서를 건드리지 않는다
(2026-10-31 재정질문/004와 같은 이유 — 추측으로 체인/우선권 로직을 손대지 않기 위함, 거짓 보고
방지).
