# 피드백 — 테스터 메모가 들어오고, 루틴이 판정을 돌려주는 자리

사용자 설계(2026-10-28). **사람 손이 중간에 끼지 않는 고리**다.

```
테스터가 판을 두며 메모   →  서버가 피드백/ 에 쌓고 깃허브로 올린다
      ↓                                   ↓
화면에 건별 판정 표시     ←  루틴이 미처리 건을 집어 고치고 판정을 적는다
```

## 파일

방 하나당 두 개가 같은 이름으로 생긴다 — `<YYYY-MM-DD>_<방이름>.{md,json}`.

- `.md` — 사람이 읽는 꼴. 깃허브 이슈 본문·내려받기가 이걸 쓴다.
- `.json` — **기계가 읽는 꼴. 루틴은 이것만 본다.**

## `.json` 꼴

```json
{
  "방": "a1b2c3",
  "덱": {"나": "호박옥", "상대": "던전마스터"},
  "시작": 1761600000.0,
  "처리": "미처리",
  "메모들": [
    {"때": 1761600123.0, "별명": "손님", "자리": "나", "턴": 3, "단계": "전투",
     "갈래": "버그", "글": "공격 대상을 어디로 끌어야 할지 모르겠다",
     "기보꼬리": ["  나: … 소환 (공격 표시)"]}
  ]
}
```

- `갈래` 는 `버그 · 헷갈림 · 제안 · 그냥` 넷 중 하나. 테스터가 고른다.
- `턴 · 단계 · 기보꼬리` 는 **서버가 적는다**(화면이 보내 준 맥락을 믿지 않는다).
  나중에 읽는 쪽이 "무슨 장면이었나"를 되짚을 수 있게 하려는 것.

## 루틴이 적어야 할 판정

처리한 파일에 `판정` 배열을 **덧붙이고** `"처리"` 를 `"처리됨"` 으로 바꾼다.
메모 번호는 `메모들` 의 1부터 센 자리다.

```json
{
  "처리": "처리됨",
  "판정": [
    {"메모": 1, "상태": "고침", "한일": "공격 대상 칸에 테두리를 켜도록 고쳤다", "커밋": "a1b2c3d"},
    {"메모": 2, "상태": "안함", "까닭": "룰지 3-3 대로라 고칠 것이 아니다"},
    {"메모": 3, "상태": "보류", "까닭": "사용자 결정 필요 — 진행.md 「미해결」 에 올렸다"}
  ]
}
```

- `상태` 는 **셋뿐** — `고침` · `안함` · `보류`. 다른 값은 서버가 버린다(화면은 「대기」로 둔다).
- `고침` 에는 `커밋`(짧은 해시)을 같이 적는다. 테스터 화면에 그대로 뜬다.
- `안함` · `보류` 에는 **까닭을 반드시** 적는다 — "어떤 게 고쳐지고 안 고쳐졌는지"를
  돌려주는 것이 이 고리의 요점이다. 까닭 없이 닫지 말 것.
- 메모를 **지우거나 고치지 않는다.** 판정만 덧붙인다.
- 판정을 적었으면 `.md` 의 `처리: 미처리` 줄도 `처리: 처리됨` 으로 맞춘다.

## 서버 쪽 동작

- `scripts/웹듀얼.py --피드백올리기` 로 띄우면 메모가 쌓일 때마다 **`피드백/` 만**
  커밋해 올린다. 다른 변경은 건드리지 않는다. `듀얼웹_공개.bat` 이 이 꼴로 띄운다.
- 서버는 2분 30초마다 `git fetch` 해서 `origin` 의 같은 `.json` 을 **읽기만** 한다
  (`git show`). 작업 트리를 안 건드리므로 판 도중에 코드가 바뀌지 않는다.
- 판정이 올라와 있으면 메모 옆에 ✅고침 / ⛔안 고침 / ⏸보류 / ⏳대기 로 뜬다.
