# 듀얼 점검 — `docs/완성_기준_듀얼.md` 여덟 항목의 실제 명령과 출력

`docs/완성_기준_듀얼.md` 8번 항목("점검 기록")이 요구하는 자리다. 항목을 끝낼 때마다 그
항목의 실제 명령과 출력 요약을 덧붙인다. 추측·"될 것이다"는 기록하지 않는다 — 돌려 본
결과만 적는다. 미구현 카드 목록(4번 항목 — 다섯 원시 동작으로 못 적는 카드)도 여기 모은다.

## 1. 상태 전이 — 통과 (2026-10-27, 81회차)

확인 방법(`docs/완성_기준_듀얼.md` 1번): `python tests/test_resolve.py` 가 다섯 원시 동작을
`게임상태`에 적용하고, 동작마다 적용 전후 상태를 확인하는 테스트가 있는가.


`engine/resolve.py` 신설 — 다섯 함수(`이동`·`카운터`·`수치`·`표시변경`·`금지`)뿐, 여섯 번째
없음(완성_기준_듀얼.md 4번 그대로 지켰다). 각 함수가 흡수하는 서술어:

- **이동** — 파괴 · 묘지로 · 되돌리기 · 제외 · 드로우 · 소환 · 특수소환 · 세트 · 덱 맨(9개 전부)
- **카운터** — 봉인 카운터 놓기 · 떼기 · 코스트 소모
- **수치** — LP 증감 · LP 배율(대미지 · 회복 · 반으로) · ATK/DEF 증감 · 배율
- **표시변경** — 앞뒤 전환(세트 해제와 별개 경로) · 공격/수비 전환
- **금지** — 발동 · 공격 · 효과 금지 이름표(상태표지 재사용, 무효 포함)

**설계 결정 두 가지(81회차, 진행.md에도 기록)**:

1. `engine/state.py` `카드인스턴스`에 `능력치증감`·`능력치배율` 두 필드를 추가했다. ATK/DEF
   보정을 저장할 자리가 기존 상태 모델에 없었기 때문이다(카운터는 있었지만 전투 수치 보정은
   없었다). 카드표의 기준 ATK/DEF와 합산하는 계산식·반올림 규칙은 **아직 정하지 않았다** —
   지금 범위(항목1)의 어떤 카드도 그 계산을 요구하지 않고, 추측으로 정하면 나중에 실제 카드가
   걸렸을 때 틀릴 위험이 있다. 효과 데이터(항목2)가 ATK/DEF 보정이 필요한 카드를 만나면 그때
   룰지 근거와 함께 정한다 — 지금은 보정치가 누적되는 것만 보장한다.
2. `금지`는 새 자료구조를 만들지 않고 기존 `카드인스턴스.상태표지`·`플레이어상태.상태표지`에
   `"금지:{무엇}:{기간}"` 꼴 이름표를 추가하는 방식으로 구현했다 — 1단계가 이미 "이름은 효과가
   정한다"로 열어 둔 자리(호박옥 「임시 봉인」)를 그대로 재사용한 것이다. 표지를 **언제 떼는지**는
   이 함수의 일이 아니다 — `docs/엔진_상태모델.md` 7장이 턴 전이 엔진(항목3)의 일로 넘겨 둔
   경계를 그대로 따랐다(새 경계를 만들지 않았다).

**회귀 확인** — `python tests/test_filter.py` 223개 그대로 통과, `scripts/맵검증.py`·
`demo_호박옥.py`·`demo_던전마스터.py` 재실행 결과 변화 없음, `python -c "from
engine.legalmoves import 커버하지_않음; print(len(커버하지_않음))"` → 0 (완성 기준 4번
유지). 1층 필터(`engine/mapfilter.py` · 맵 YAML · 기존 테스트)는 건드리지 않았다.

## 2. 효과 데이터 — 통과 (2026-10-27, 사용자 세션)

확인 방법(`docs/완성_기준_듀얼.md` 2번): `python scripts/효과검증.py` — 두 덱 카드 전수에
`cards/효과/<덱>.yaml` 항목이 있고 로더가 전부 파싱하는가. 다섯 동작으로 못 적은 카드가
**사유와 함께** 비워져 있는가.

```
$ python scripts/효과검증.py
효과 데이터 로드: 카드 41종

[호박옥] 카드 23종 · 효과 54개
  구현 24 · 사유 적힌 빈자리 30 · 안 적힘 0

[던전마스터] 카드 18종 · 효과 42개
  구현 12 · 사유 적힌 빈자리 30 · 안 적힘 0

============================================================
합계 — 구현 36 · 빈자리 60 · 안 적힘 0
전체 결과: 통과 (모든 효과가 구현되었거나 사유와 함께 비워져 있다)
```

**안 적힌 효과 0건**이 통과 조건이다. 빈자리 60개는 실패가 아니라 「빈자리는 정답, 추측은
실패」 원칙대로 사유를 적어 둔 것이다. 사유는 네 범주로 수렴했다:

| 약호 | 사유 | 건수(대략) |
|---|---|---|
| (가) | **[지속] 상시 효과** — 발동이 아니라 "필드에 있는 한 계속 적용"(2026-10-26 판정). 상시 효과 적용 모델이 따로 필요하다 | 25 |
| (나) | **강제 트리거** — 플레이어가 고르는 수가 아니다(2026-10-27 판정 #4). 턴 전이 엔진이 자동으로 걸어야 하는데 트리거 처리가 없다 | 14 |
| (다) | **가변 개수** — "임의의 개수만큼 제거하고 그만큼" 꼴. 합법수 문자열은 `제거개수=` 로 넘기는데 효과 적용기에 그 인수를 전달하는 경로가 없다 | 4 |
| (라) | **반응형 트리거** — "상대가 ~했을 때"의 타이밍 훅이 없다 | 8 |

나머지는 카드별 개별 사유이고, 그중 **룰 질문이 안 닫혀서** 비운 것(`미해결`)은 3건이다 —
던전마스터 깜짝상자 2번 · 트랩: 깜짝상자 1번 · 데스 칠 드래곤 1번. 전부 `진행.md` 「미해결」에
이미 올라 있는 항목이고 사용자 판정 없이는 추측이 된다.

**다섯 원시 동작 밖으로 나간 효과는 하나도 없다.** 적을 수 없는 것은 전부 "구조가 아직
없어서"(가·나·다·라)이지 "여섯 번째 동작이 필요해서"가 아니다 — 원시 동작 다섯이라는 결론은
이번 작업으로 반증되지 않았다.

> **갱신 (2026-10-27, 83회차)** — 위 표의 (다) 행("효과 적용기에 그 인수를 전달하는 경로가
> 없다")은 이제 지난 상태다. 통로를 열어 아우렘 티라누스 4번 · 균열 1번 두 건을 채웠다 —
> 아래 「이름붙은 인수 통로」 절 참조. 숫자는 `python scripts/효과검증.py` 로 다시 확인:
> **구현 38 · 사유 적힌 빈자리 58 · 안 적힘 0**(호박옥 24→26, 던전마스터 12 그대로).
> 위 명령·출력 블록은 **그 시점(사용자 세션)의 기록**이라 그대로 두고, 바뀐 숫자는
> 여기와 「이름붙은 인수 통로」 절에만 적는다.

## 3. 턴 루프 — 통과 (2026-10-27, 사용자 세션)

확인 방법: `python scripts/듀얼.py --시드 1 --나 무작위 --상대역할 무작위` 로 한 판이 예외
없이 끝까지 가는가.

```
$ python scripts/듀얼.py --시드 1 --나 무작위 --상대역할 무작위 --조용히
...
[턴 8 · 나]
  나: 메인덱 드로우 (월식)
  나: 월식 로드
  나: 호박옥의 수호자 - 카르분쿨루스 직접공격 → 상대 HP -3000
— 종료: 나 승 (a) · 룰지 4장 a — 한 쪽의 HP가 0
```

`engine/turn.py` 신설 — 수 문자열 해석(`ast.literal_eval` 만 쓴다, `eval` 금지) · 수 적용
(소환 · 표시변경 · 공격선언 · 로드 · 세금차감 · 발동) · 전투(룰지 3-3 표 여섯 행 그대로) ·
단계 전이 · 승패. 상태를 바꾸는 일은 **전부 `engine/resolve.py` 를 거친다.**

단계는 준비 → 진행 → 전투 → 정비 → 종료로 돌고, 각 단계에서 합법수가 빌 때까지(또는
플레이어가 「더 안 둠」을 고를 때까지) 수를 받는다.

## 4. 덱 · 드로우 — 통과 (2026-10-27, 사용자 세션)

확인 방법: 같은 시드로 두 번 실행해 패와 전개가 같은가.

```
$ python tests/test_duel.py
ok   덱_같은_시드면_초기패와_선공이_같다
ok   덱_초기패는_5장
ok   덱_HP는_5000
ok   덱_상급덱은_레벨5이상만
ok   한판_같은_시드면_같은_결과
```

`engine/deck.py` — 룰지 2장 그대로. 스킬 카드 태그로 덱 구성(공용 태그 포함), 레벨 0~4는
메인 덱 · 5~10은 상급 덱(룰지 1-1), HP 5000, 두 덱 셔플, 주사위로 선후공(같은 눈이면 다시),
초기 패 총 5장(룰지 2-2).

**미구현 (사유 있음)** — 전략 덱(0~20장)과 멀리건(2-2의 "1회에 한해 되돌리고 다시 뽑기")은
만들지 않았다. 한 판을 두는 데 필요하지 않고, 어느 카드를 되돌릴지는 사람의 선택이라 자동
대전에서 정할 근거가 없다. 같은 이유로 주사위를 이긴 쪽이 선후공을 **고르는** 선택도
구현하지 않고 "이긴 쪽이 선공"으로 뒀다.

카드 매수는 각 1장씩이다 — 룰지 2장이 같은 카드의 매수 상한을 말하지 않아 추측으로
늘리지 않았다.

## 6. 상대 역할 — 통과 (2026-10-27, 사용자 세션)

확인 방법: 자가 대전 100판이 예외·무한 루프 없이 완주하는가.

```
$ python scripts/듀얼.py --시드 100 --나 필터 --상대역할 무작위 --판수 100 --조용히
100판 — 나 78승 · 상대 22승 · 미정 0
```

`engine/players.py` — `무작위플레이어`(합법수 균등 추출)와 `필터플레이어`(합법수 → 1층 맵
거르기 → 남은 것에서 추출). **1층은 순위를 매기지 않으므로**(맵_형식.md 7장) 필터가 남긴
후보 중 첫 번째를 고르지 않고 무작위로 뽑는다 — 맵에 적힌 순서를 선호로 오해하면 아직 없는
상위 층의 일을 1층이 몰래 하는 셈이 된다.

미정 0 = 200턴 상한에 걸린 판이 없다는 뜻이다(무한 루프 없음).

필터 쪽 78승은 **1층 맵이 실제로 수를 좁히고 있다**는 관측이지 강함의 증명이 아니다 —
상대가 무작위이고, 효과 60개가 아직 미구현이라 판의 모양 자체가 완전하지 않다.

## 7. 사람 인터페이스 — 통과 (2026-10-27, 사용자 세션)

확인 방법: `python scripts/듀얼.py --덱 호박옥 --상대 던전마스터` 로 보드 · 합법수 번호 입력 ·
기권 · 기보 저장이 되는가. **비대화 모드로 한 판 완주한 기록**이 있는가.

```
$ python scripts/듀얼.py --덱 호박옥 --상대 던전마스터 --시드 2 --수 0 0 0     --기보 기보.txt < /dev/null
...
  상대: 던전마스터 새크리파이스 2번 발동
    → 던전마스터 다크엘프 어새신 아카이브 → 유닛존
  상대: 던전마스터 다크엘프 어새신 직접공격 → 나 HP -2000
— 종료: 상대 승 (a) · 룰지 4장 a — 한 쪽의 HP가 0
기보 저장: 기보.txt
```

보드에는 양쪽 HP · 패 · 덱 매수 · 유닛(능력치 · 표시 · 카운터) · 이펙트가 뜨고, 자기 패는
`data/card_pool.json` 의 `text` **원문 그대로** 같이 보여 준다(완성_기준_듀얼.md 7번의
「카드명 + text 원문」). 빈 줄은 「더 안 둠」, `q` 는 기권이다.

비대화 실행에서 표준입력이 닫히면 되묻지 않는다 — `isatty()` 가 쉘에 따라 True 를 내놓기도
해서(Git Bash에서 확인) EOF 를 한 번 만나면 그 뒤로는 묻지 않도록 했다.

## 웹 화면 — 룰지 0장 배치 그대로 (2026-10-27, 사용자 세션)

**애초에 안 보낸다**(상대의 뒷면 카드는 룰지 1-1, 남의 패). 브라우저 개발자 도구로도 안

  추측으로 `유언직후()`를 재사용하지 않았다. `강제: true` 틀 자체(발동조건 항목 + 건너뛰기 +
  `강제효과_후보들`)는 그대로 재사용할 수 있으니, 다음에 반응형 트리거를 열 때 이 네 장이
  자연스러운 첫 대상이다(사유를 그렇게 고쳐 적어 뒀다 — `cards/효과/호박옥.yaml`).

  없다"로 좁혀졌을 뿐이다.
- **[지속] 상시 효과(가)와 반응형 트리거(라, [유언]·[소환] 아닌 쪽)는 손대지 않았다** —

## 반응형 트리거 — 깨어남의 종 (HP 임계값, 85회차, 「알려진 틈」 1번의 첫 조각)

확인 방법 — 룰지 1-2 "트리거 — 특정 상황에 반응해서 **패 또는 필드**에서 발동하는 이펙트
카드. 로드해 둔 상태에서도 조건이 맞으면 발동한다"를 그대로 따른다. 카드 텍스트(깨어남의
종): "자신의 HP가 2000 이하가 되었을 때 자신 필드의 「호박옥 - 녹스 솜니페르」에 놓인 봉인
카운터를 전부 제거하고 발동. 제거한 카운터 수까지 묘지에서 「호박옥」 몬스터를 특수소환한다.
(이 효과는 강제로 발동한다.)"

**무엇을 열었나.**

1. `engine/predicates.py` `이펙트존.있음(카드명)` 신설 — `필드.있음()`(→`필드카드들()`)은
   기본값이 앞면만이라 **로드되어 뒷면인** 트리거 마법을 놓친다. 룰지 1-2가 뒷면 상태에서도
   발동 후보로 세라고 명시하므로 새 조회를 열었다(`패.있음()`과 or로 묶어 "패 또는 필드"
   둘 다 커버한다).
2. `engine/legalmoves.py` `강제효과_후보들()` — 반환 꼴을 `(카드이름, 번호)`에서
   `(카드이름, 번호, 인수)`로 늘렸다. 82·83회차가 연 "이름붙은 인수"(`제거개수=...`) 통로는
   **합법수 문자열**이 실어 오는 값이라 강제 효과(합법수가 아니다)에는 원래 전달 경로가
   없었다 — 깨어남의 종의 "제거한 카운터 수까지"는 플레이어가 고르는 게 아니라 카드 텍스트가
   "전부 제거"로 이미 정해 둔 값이라, `cards/발동조건/<덱>.yaml` 항목 자체에 `인수: {제거개수:
   잔량전부}`를 적어 두고 이 함수가 그대로 돌려주게 했다. `engine/turn.py`
   `강제트리거_처리()`도 `인수={}` 고정값 대신 이 사전을 그대로 넘기도록 고쳤다.
3. `engine/turn.py` `강제트리거_처리()` — 카드를 찾는 자리를 `쪽.아카이브`뿐이던 것에서
   `_카드찾기_어디든()`(유닛존·이펙트존·패·아카이브)으로 넓혔다(84회차의 강제 [유언]은 늘
   아카이브에 있었지만 강제 [트리거] 마법은 패·필드에도 있을 수 있다). 효과 적용이 성공하면
   `_발동후_이동()`(82회차)도 불러 구분별 이동을 그대로 태운다 — 기존 강제 [유언] 여덟 장
   (몬스터 효과, `type != "마법"`)에는 그 함수가 스스로 아무것도 안 해 영향이 없다.
4. `engine/effects.py` — (a) `_이동적용`의 "에서 · 로"(목록형 존 검색) 꼴도 `_수값()`을 타게

   다른 카드**(녹스 솜니페르)를 가리켜야 하는 경우를 위해서다.
5. `cards/발동조건/호박옥.yaml` · `cards/효과/호박옥.yaml` — 깨어남의 종 1번을 채웠다.

## 효과 문면을 화면에 붙였다 (2026-10-28, 사용자 세션)

**사용자 요청** — "어떤 효과를 사용했는지 알려줘야지. 다 적어두면 힘들어". 기보와 수
선택지가 `호박옥 - 잔편 1번 발동` 뿐이라, 카드 텍스트를 따로 적어 두지 않으면 무슨 일이
일어나는지 읽을 수 없었다. 같은 세션이 「알려진 틈」 1번(몽마의 도래)도 사용자 판정으로
닫았다 — "파괴한 몬스터" = 파괴당한 자신의 「호박옥」 몬스터이고, 발동 시점에 이미
아카이브에 있는데 아카이브엔 뒷면 상태가 없어(룰지 0-3 `:100`) 적용할 자리가 없다 — 늘
불발이라 구현 대상이 아니다. 근거는 `rules/충돌목록.md` 「판정 (2026-10-28, 사용자)」
#6·`cards/효과/호박옥.yaml`에 적었다(이 문서에는 중복하지 않는다).

**규칙은 안 건드렸다 — 보여 주기만 하는 층이다.** `engine/view.py` 에 네 함수를 더했다.

- `효과조각들(텍스트)` — 카드 `text` 를 효과 번호별로 쪼갠다. **번호가 1부터 하나씩 늘어나는
  것만** 머리로 인정해서, 「럭키 다이스」의 "- 1: … - 6: …" 가짓수 목록이나 문장 속 숫자를
  효과 머리로 잘못 읽지 않는다(그 카드는 효과가 1번 하나로 나온다 — 시험으로 고정).
- `효과문(표, 카드이름, 번호)` · `수_효과문(수, 표)` — 합법수 `발동('카드', N)` 에서 그 번호의
  문면을 뽑는다. 발동이 아닌 수(`소환(...)` 등)에는 아무것도 안 붙인다.
- `기보_효과문(줄들, 표)` — 「…N번 발동」 줄(강제 발동·효과 미구현 포함) 바로 아래에
  `「문면」` 한 줄을 끼운다. **원본 기보는 그대로 둔다** — CLI와 테스트가 쓰는 줄 꼴이라
  건드리면 안 되고, 이건 화면용 사본이다(`engine/room.py` 상태딕에서만 통과시킨다).

브라우저 쪽(`scripts/웹듀얼.py`)은 선택지 버튼 안에 문면을 흐린 두 번째 줄로 깔고, 기보의
`「…」` 줄은 강조색으로 뺀다. 카드 문면이 `innerHTML` 로 들어가므로 `벗기기()`(textContent
경유)로 한 번 이스케이프한다.

**실측**
- `tests/test_duel.py` 157개(효과 문면 4 신설) 전부 통과 — 가짓수 목록 오독 방지,
  발동 아닌 수에 안 붙는 것, 원본 줄 불변까지 시험에 넣었다
- `tests/test_filter.py` 223개 · `tests/test_resolve.py` 19개 회귀 없음
- 서버를 실제로 띄워(HTTP) 한 판 두며 확인 — 버튼: `발동('호박옥 - 잔편', 1)` 아래
  "[신속] 자신 필드에 「아우렘 티라누스」 이외의 몬스터가 존재하지 않을 때 발동. …",
  기보: 같은 문면이 발동 줄 아래에 들어왔다
- 페이지 자바스크립트를 뽑아 `node --check` 통과

**덧(같은 날) — 끊긴 연결 트레이스백을 삼킨다.** 화면이 0.9초마다 폴링하므로 탭을 닫거나
새로고침하면 그 순간의 요청이 중간에 끊기고(`ConnectionResetError` WinError 10054 등),
`ThreadingHTTPServer` 기본 동작이 서버 창에 트레이스백을 통째로 찍었다 — 서버는 멀쩡한데
창만 덮인다. `듀얼서버(ThreadingHTTPServer)` 를 세워 `handle_error()` 에서 **연결 끊김 세
종류만**(`ConnectionResetError`·`ConnectionAbortedError`·`BrokenPipeError`) 삼키고 나머지
예외는 평소대로 올린다(진짜 버그를 가리지 않는다). 소켓을 RST 로 세 번 끊고 확인 — 서버
창에 아무것도 안 찍히고 그 뒤 요청이 HTTP 200 으로 정상 응답한다.

## 94회차 — 「알려진 틈」 3번의 (c) "필드 전역 보호"를 닫았다 — [지속] 상시 효과 세 조각 전부 끝

## 화면을 제스처로 바꿨다 — 마스터 듀얼식 (2026-10-28, 사용자 세션)

**사용자 요청** — "직접 드래그 해서 내고, 카드의 효과 발동은 카드를 눌러서 처리하는 방식.

방식이 직관적이긴 해도 손에 안 붙는다는 것.

**규칙은 한 줄도 안 옮겼다.** 합법수는 여전히 `engine/legalmoves.py` 가 만들고, 화면은
그 문자열을 판 위 위치에 묶기만 한다. 자바스크립트로 판정을 옮기면 정본이 둘이 된다.

  이름붙은 인수가 붙은 수(`발동(..., 제거개수=3)`)는 `곁다리=True` 로 표시해 **화면이

| 직접 공격 | 내 유닛 → **상대 HP 띠** 로 끌기 | `공격선언('카드')` |
| 효과 발동 · 표시 바꾸기 | **카드를 누른다** → 그 카드의 수 메뉴 | `발동('카드', N)` · `표시변경(...)` |
| 대상 고르기 | 판에서 **그 카드를 누른다** (후보는 초록 테두리) | `고르기` 질문의 답 |

끌기 시작하면 받을 수 있는 자리만 켜지고, 한 자리에 수가 둘 이상 묶이면(패 카드를
이펙트 존에 놓을 때 로드와 발동이 다 가능한 경우 등) 그 자리에서 작은 메뉴로 묻는다.
둘 수 있는 수가 있는 카드는 테두리와 개수 뱃지가 붙는다. 제스처로 못 줄이는 수와
`모든 수 (N)` 접이식 목록은 그대로 남겨 뒀다 — **제스처가 수를 가리지 않는다.**
