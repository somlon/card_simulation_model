# 대전 논리 설계 — 헤아림 플레이어 (2026-10-29)

사용자 지시: "기존 덱이 돌아가는 논리가 부실해 … 룰지를 기본으로 깔고 가되, 재정에
벗어나지 않게 구성해줘." 구현은 `engine/players.py` 끝 절, 시험은 `tests/test_policy.py`.

## 왜 이렇게 생겼나 — 규칙을 지키는 방법이 곧 설계다

AI가 룰지·재정을 어기지 않게 하는 길은 둘이다 — ① 규칙을 AI 안에 다시 적고 어기지
않도록 조심한다, ② **AI 가 규칙을 아예 모른 채, 규칙의 유일한 정본(엔진)이 내놓는
것만 다루게 한다.** 이 설계는 ②다.

1. **고르는 것은 합법수뿐** — `engine/legalmoves.py` 가 내놓은 수만 후보다.
   규칙 위반 수는 애초에 후보에 없으므로 어길 방법이 없다.
2. **수의 결과는 엔진 시뮬레이션으로만 안다** — 후보마다 상태를 복사해
   `turn.수_적용` + `강제트리거_처리` 를 실제로 돌리고, 나온 상태를 평가한다.
   규칙 해석을 AI 쪽에 두 번째로 적으면 정본이 둘이 된다. 그래서 안 적는다.
   **룰이나 재정이 바뀌어도 엔진만 고치면 AI 는 자동으로 따라온다.**
3. **평가는 공개 정보만** — 상대 패·덱은 장수만, 뒷면 유닛은 고정 몸값(300)으로만.

## 층 구조 (기존 설계와 잇는다)

```
0층  합법수        engine/legalmoves.py   — 규칙 (정본)
1층  경질 필터     maps/<덱>.yaml         — "절대 하지 마라" (있는 덱만, 기존 그대로)
2층  헤아림 평가   engine/players.py      — 1수 앞 시뮬레이션 + 상태값()   ← 이번에 신설
3층  (자리만) 성향·심리                   — 아래 「다음 단계」
```

1층 필터는 **순위를 매기지 않는다**는 기존 원칙 그대로 두고, 순위는 2층이 매긴다.

## 상태값() — 덱 중립 평가 함수

근거는 전부 룰지다. 가중치는 기본 단위 1 LP = 1점.

| 항 | 가중 | 룰지 근거 |
|---|---|---|
| HP 차 | ×1 | 4-a HP 0 패배 |
| 판 위 전투력(내 ×0.45 / 상대 ×0.55) | | 3-3 전투표 — 공격 표시는 공격력, 수비는 수비력 |
| 유닛 수(내 +150 / 상대 −170) | | 3-3 직접공격 — 유닛이 없으면 본체가 맞는다 |
| 패 ×90 · 이펙트존 ×60 | | 1-2 — 쓸 수 있는 선택지의 수 |
| 덱 잔량 ≤6장이면 장당 ∓500 | | 4-b 덱아웃 패배 |
| 카운터 ×40 | | 6장 — 효과의 연료 (덱 중립이라 가볍게) |
| 공유 존 마커 ±80 | | 0-5 뒤집힘 페널티 |
| 직접 치명권 −2500 | | 내 필드 0 + 상대 공격 표시 ATK 합 ≥ 내 HP |

즉승이 보이면 그 수(+10⁹), 즉시 패배하는 수는 회피(−10⁹). 하위 선택(대상 고르기 등)은
표본을 여러 번 뽑아 가장 좋았던 답 조합을 기억해 두고 **진짜로 둘 때 그대로 재연**한다 —
시뮬과 실적용이 같은 엔진 코드를 지나므로 질문 순서가 같다(어긋나면 그 자리에서 무작위
낙하 + 대기열 비움).

예산: 후보 ≤8이면 표본 2, 그 위는 1 · 후보 >24면 24개 무작위 추림 · 복사는 pickle 왕복
(deepcopy 대비 수 배 빠름, 프로파일로 확인).

## 알고 있는 한계 (없는 척하지 않는다)

- **1수 앞만 본다.** 상대 턴 응수는 「직접 치명권」 항으로만 어림한다.
- 시뮬 복사본에 내 덱 순서가 실려 있어 "덱 위 N장" 효과의 결과를 실제보다 정확히 아는
  작은 엿보기가 있다 — 평가가 장수만 세서 영향은 미미.
- 미구현 효과는 시뮬에서도 상태를 안 바꾸므로(엔진과 같은 경로) 그 카드를 과소평가한다.
  **효과가 채워질수록 AI 도 저절로 강해진다** — 별도 작업 불요.

## 다음 단계 — 사용자 구상(최적화 → 학습 → 심리층)에 대한 로드맵

사용자 구상은 단계만 지키면 좋은 방식이다. 순서를 어기면 함정이 하나 있다.

1. **가중치 자기대전 튜닝 (다음에 할 것, 싸다)** — `상태값()` 의 가중 10여 개를 자기대전
   승률로 언덕오르기/교차엔트로피 탐색. CPU 만으로 돌고(판당 0.15초 → 1000판 3분),
   결과가 숫자 몇 개라 검증·되돌리기가 쉽다. 덱별 가중 YAML(`cards/성향/<덱>.yaml`)로
   저장하면 "덱 성향"이 데이터로 남는다.
2. **상대 모델링(심리층의 뼈대)** — 상대의 로드·발동 이력에서 "뭘 아끼고 있나"를 추정하는
   술어들. 학습 전에 설계로 먼저 — 셔플! 정보 재정(재정질문 005)이 갈림길이다.
3. **그 다음에야 학습** — 신경망 평가/정책은 효과 구현이 충분히 채워진 뒤에. **지금
   학습하면 미구현 상태에 과적합**되어 효과를 채울 때마다 다시 학습해야 한다(유일한 함정).
   8GB VRAM 원칙 안에서는 작은 MLP 평가망 + 자기대전이면 충분하고, 그마저도 1번의
   가중 튜닝으로 얻는 폭이 먼저다.
