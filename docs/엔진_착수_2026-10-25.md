# 엔진 착수 — 1층 맵 필터가 실제로 돈다 (2026-10-25)

맵 형식 결정 3개가 끝난 뒤, 설계 문서만 있고 코드가 0줄이던 상태를 깨고 **1층 필터를 실행 가능한
형태로** 구현했다. 돌려 보기 전에는 알 수 없던 갭이 여덟 개 나왔고, 그게 이 회차의 주 산출물이다.

```
python scripts/demo_호박옥.py     # 손으로 만든 국면 5개에 호박옥 맵을 돌린다
python tests/test_filter.py       # 32개 테스트 (pytest 없이도 돈다)
```

## 1. 실제로 되는 것

`docs/맵_형식.md` 7장이 그린 경로 중 **1층만** 돈다.

```
합법수 집합 → [1층 맵 필터 ← 지금 이것] → 후보 집합 → (후속 필터: 심리 등) → 행동 분포
     ↑ 없음                                                  ↑ 없음
```

- `maps/호박옥_봉인의_계약.yaml` 을 읽어 A·B·C·D 네 노드를 우선순위 순으로 평가한다
- 간선의 `조건` 을 식 언어로 평가해 참인 간선의 `후보` 를 모으고, 노드 전체에서 모은 `금지` 로 깎는다
- 노드의 `불변식` 을 검사하고, 깨지면 `위반시.식` 으로 자해 수치까지 계산한다
  (잔고 1 → 1000, 필드 전멸 → 2000 — 맵 3-6 과 일치)
- 통과 후보에는 **점수가 없다.** 1층은 경질 필터이므로 통과/탈락과 그 이유만 낸다(7-1 · 7-2)

### 구성

| 파일 | 하는 일 |
| --- | --- |
| `engine/expr.py` | 식 언어 — 산술 비교 · and/or/not · 함수 호출**만**. 분기 · 반복 · 변수 정의는 파서가 거부한다(제안서 5장의 약점을 문법으로 막았다) |
| `engine/action.py` | 행동 서술자(`후보` · `금지`) 읽기 + 금지 대조. 식과 **다른 언어**다 — `'제거'\|'재전개'` 합집합과 `잔량>=1` 제약을 받아야 해서 더 느슨하다 |
| `engine/state.py` | 아홉 개 존 + 패, 카드 인스턴스, 턴 상태 — `docs/엔진_상태모델.md` 1~3 · 6장 |
| `engine/static.py` | 정적 테이블 + 전처리. 8장이 꼽은 두 갭(`대상지정`, 수입 분류)을 로드 시 한 번만 해결 |
| `engine/predicates.py` | 술어 라이브러리 — 4장 목록 전부 + 맵이 추가한 것들. **덱 중립**이고 덱별 수는 맵이 `덱상수` 로 넘긴다 |
| `engine/mapfilter.py` | 맵 로드 · 검증 · 거르기 |
| `data/수입분류.json` | 맵 3-3 의 확정/조건부 표를 구조화한 정적 캐시 |

### 결정한 것 (루틴이 `진행.md` 「미해결」 에 올려 두라고 했던 것)

- **언어는 Python 3.12**, 의존성은 `pyyaml` 하나. 탐색 속도가 문제가 되는 지점에서 뜨거운 부분만
  옮기는 쪽이 맞고(목표_수준.md 4장), 지금 필요한 건 "맵이 맞게 적혔는지" 확인이다
- **디렉터리**는 `engine/`(코드) · `tests/` · `scripts/`. 맵과 문서는 자리를 그대로 둔다
- 식별자는 한국어로 쓴다. 맵 · 룰지 · 재정이 전부 한국어라 번역 층을 두면 대조가 어려워진다

## 2. 돌려 보고 나온 갭 여덟 개

앞의 둘은 고쳤고, 나머지 여섯은 **사용자/맵 쪽 결정이 필요해** 손대지 않고 `진행.md` 에 올렸다.

### 고친 것

1. **카드 이름 오류** — YAML B 노드가 `'호박옥의 수호자 - 황금봉랍'` 으로 적었지만 황금봉랍은
   수호자가 아니라 마법 카드(`AMBR-012`, `호박옥 - 황금봉랍`)다. 카드 풀에 없는 이름이었다.
   → 두 군데 교정. `tests/test_filter.py::test_맵의_모든_카드이름이_카드풀에_있다` 가 재발을 막는다
2. **`덱상수` 블록이 없었다** — `지출가능() = 잔고 − 세금 − 벽유지분()` 을 돌리려면 세금 값(2)이
   필요한데 맵에 없었다. 술어를 덱 중립으로 유지하려면 덱별 수는 맵이 넘겨야 한다(4장).
   → YAML 머리에 `덱상수: {세금: 2, 카운터명: 봉인}` 추가 (근거는 .md 3-1 · 1장)

### 결정하고 구현한 것 (2026-10-25, 사용자: 「빈자리 알아서 채워줘」)

여섯 개 다 메웠다. 맵 스키마에 축 세 개가 늘고 술어 네 개가 생겼다.

3. **「기본 금지 + 조건부 예외」** → 간선에 **`예외:`** 축. 깨는 금지를 건 **간선의 이름**을 적는다.
   맵 4-6 이 「금지선보다 우선한다」고 말로 적어 둔 것을 데이터로 옮긴 자리다. 예외가 조용히
   작동하면 안 되므로 필터 결과에 「예외로 깬 금지」로 보고한다.
   적용: D `티라누스 전환 허가` → `티라누스 비우기 금지 (기본)`,
   B `체인 방어 예외` → `지출 가능 게이트` · `유일 몬스터 보호`
4. **추상 동작과 구체 동작의 어휘** → 간선에 **`자원:`** 과 **`목적:`** 축. `<자원>지출` 꼴의
   추상 동작 금지(`카운터지출`)는 개별 후보가 아니라 **간선 속성**과 대조한다. 목적은 원래
   후보 하나하나가 아니라 간선의 성질이기 때문이다(C 노드의 제거 간선들은 전부 목적=제거).
   자원을 안 쓰는 간선은 `자원: 없음` 으로 **명시**한다 — 미선언이면 검증이 집어낸다
5. **후보/금지 안의 술어 호출** → **1층이 푼다.** 금지 대조 때 술어를 평가해 구체 대상으로
   치환한다. 안 풀면 `금지: 세금차감(임시봉인상태유닛())` 이 영원히 작동하지 않고, 그러면
   함정을 박아 둔 금지의 존재 이유가 사라진다. 금지 쪽이 집합이면 「후보가 그 안에 있으면 차단」
6. **`타격합`** → 엔진이 **`타격합()`** 술어로 제공. 공격 가능 여부는 규칙 판정이라 엔진 몫이다.
   **수비 표시라도 표시 변경이 가능하면 센다** — 맵 5-3 은 조건 2(리설)와 조건 4(표시변경가능)를
   하나의 계획으로 보므로, 지금 공격 표시인 것만 세면 전환 전에는 조건 2가 영원히 거짓이 된다
7. **`벽유지분()` 의 책임** → 맵이 **리스트가 아니라 기준값**(`덱상수.벽유지최소`)을 넘긴다.
   호박옥은 1(맵 3-5). `벽유지분() = 면역유닛수 × 벽유지최소`, `면역유닛()` 은 카운터가
   기준값 이상인 유닛. 덱 중립은 유지되고 맵은 숫자 한 개만 들고 있으면 된다
8. **서술형 불변식** → B 노드를 **`면역유닛수() == 필드.몬스터수()`** 로 식화. 식 언어에
   수량자를 넣지 않고 집계 술어로 풀었다(언어를 작게 유지하는 것이 맵_형식.md 5장의 결정).
   몬스터 0장이면 양쪽이 0이라 **공허참** — 제약 대상이 없는 상황을 위반으로 세지 않는다

결과: `맵_검증` 이 **문제 없음**, 필터의 「평가 불가」·「보류」가 **0건**이 됐다. D 노드의 다섯
조건이 참인 국면에서 전환 후보 3개가 정상적으로 나온다(전에는 자기 금지에 걸려 사라졌다).

## 3. 하지 않은 것 — 다음 차례

- **합법수 생성(규칙 엔진)** — 이게 1층과 엔진 사이에 남은 유일한 미구현 경계다. 지금은
  `게임상태.가용수단` 을 바깥에서 채워 넣는 입력으로 두고, `확정수입()` 의 발동형 수입이 그것을 읽는다
  (맵 3-3 의 "내가 이번 턴에 직접 놓는다"를 세려면 실행 가능 여부가 필요하다)
- **후속 필터(심리 층)** — 가중치가 들어가는 자리. 7-2 대로 던전마스터 정보 은닉 축이 풀린 뒤에 설계
- **속도 최적화** — 상태모델 9장의 네 가지(카운터 정수 enum, 고정 배열 배치, 되돌리기 레코드,
  합법수 룩업)는 **하나도 적용하지 않았다.** 벤치마크와 함께 할 일이고, 지금 하면 측정 없이 추측으로
  최적화하는 셈이다
- 던전마스터 맵은 아직 `.yaml` 이 없다. 호박옥 YAML 이식(침전 6장 · 상대 덱별 분기 7장)도 남았다

## 4. 왜 이 순서였나

맵 YAML 이 네 노드까지 쓰였는데 아무도 그걸 읽어 본 적이 없었다. 더 쓰기 전에 한 번 돌려 보는 것이
싸다 — 실제로 돌려서 **카드 이름 오류 하나와 스키마 갭 여섯 개**가 나왔고, 이 중 3·4·5번은 남은
노드(침전 · 상대 덱별 분기)와 던전마스터 맵에도 똑같이 걸린다. 틀을 고치고 나서 옮기는 쪽이
다 옮긴 뒤 고치는 것보다 싸다.
