# 맵 커버리지 — 측정 기준

마인드맵을 덱마다 사람이 쓰는 이상, **맵의 완성도 차이가 승률 차이로 샌다.**
달그림자 맵을 꼼꼼히 쓰고 세제 맵을 대충 쓰면 달그림자가 이긴다 — 그런데 측정하려는 것은 덱의 강함이지 맵의 완성도가 아니다.

이 문서는 그 새는 구멍을 **숫자로 막는** 방법을 정한다.

## 1. 무엇을 재는가

### 정적 지표 — 맵이 얼마나 쓰여 있는가

| 지표 | 세는 법 |
| --- | --- |
| 노드 수 | 목표 · 상태 노드의 개수 |
| 간선 수 | 조건 → 후보 규칙의 개수 |
| 조건식 수 | 수치로 판정하는 식의 개수 (예: `지출 가능 = 잔고 − 세금 − 벽값`) |
| 분기 노드 수 | 상대 덱에 따라 갈리는 노드의 개수 |

정적 지표는 **작성 진도**를 보는 용도다. 덱 간 비교의 기준으로 쓰지 않는다 (3장 참조).

### 동적 지표 — 맵이 실제로 작동했는가

| 지표 | 정의 |
| --- | --- |
| **침묵률** | 전체 의사결정 지점 중, 맵이 후보를 좁히지 못해 공통 로직으로 넘긴 비율 |
| 제한율 | 맵이 개입한 지점에서 (합법수 → 후보)로 줄인 평균 비율 |
| 단독 지정률 | 맵이 후보를 1개로 확정한 지점의 비율 |

침묵률이 핵심 지표다. 나머지 둘은 맵이 **지나치게 좁히고 있지 않은지**(단독 지정률이 너무 높으면 탐색이 무의미해진다)
확인하는 보조 지표다.

## 2. 침묵 로그

맵이 침묵한 지점은 전부 기록한다. 이 로그가 **다음에 채울 맵 목록**이 된다.

기록할 항목:

```
{
  "deck":        "호박옥-봉인의 계약",
  "opponent":    "세리-세제",
  "phase":       "진행 단계",
  "node":        "C",              // 침묵한 노드. 어느 노드에도 안 걸렸으면 null
  "legal_count": 14,               // 그 시점의 합법수 개수
  "state_key":   "...",            // 상황 요약 (잔고, 필드, 패 매수 등)
  "chosen_by":   "공통탐색",
  "result":      "..."             // 그 판의 승패 — 침묵 지점의 중요도 가중에 쓴다
}
```

집계 방법:

- `state_key` 로 묶어 **빈도순 정렬** → 자주 나오는 상황부터 맵에 채운다
- 승패와 함께 보면 **어디서 침묵하면 실제로 지는지**가 나온다. 빈도만으로 정렬하면 사소한 상황이 위로 올라올 수 있다
- `legal_count` 가 큰 지점의 침묵이 더 비싸다 — 후보를 못 좁힌 채 넓은 공간을 공통 로직에 떠넘긴 것이기 때문

## 3. 덱 간 동등성의 기준은 「침묵률」이지 「노드 수」가 아니다

노드 수를 맞추는 것은 틀린 기준이다. 덱마다 복잡도가 다르기 때문이다 —
단순한 덱은 적은 노드로도 침묵률 0에 가깝게 갈 수 있고, 복잡한 덱은 노드가 많아도 여전히 침묵한다.
**노드 수를 맞추면 단순한 덱의 맵을 쓸데없이 부풀리고 복잡한 덱의 맵을 모자란 채로 남긴다.**

> **동등성 기준** — 모든 덱의 침묵률이 비슷할 것. 노드 수는 그 결과일 뿐이다.

## 4. 밸런스 측정의 게이트

밸런스 수치는 아래를 **모두** 만족할 때만 유효하다. 하나라도 어기면 그 수치는 덱이 아니라 맵을 재고 있다.

```
게이트 1   모든 덱의 침묵률 ≤ 10%
게이트 2   덱 간 침묵률 편차 ≤ 5%p
게이트 3   학습이 고정(freeze)되어 있고 버전이 기록되었다
게이트 4   덱당 표본이 충분하다 (±1%p 판정에 약 1만 매치)
```

- 임계값 10% · 5%p 는 **첫 제안값**이다. 실제 분포를 보고 조정한다
- 게이트 1 · 2는 맵이 모자란 상태에서 낸 승률을 「덱 밸런스」로 읽지 않기 위한 장치다
- 게이트 3 · 4는 기존 저장소에서 이미 확인된 함정이다 — 학습표 공백 때문에 같은 덱이 78.9% ↔ 91.4% 로 튀었다

## 5. 측정 순서

```
1. 맵 작성            → 정적 지표로 진도 확인
2. 자가대전 (소표본)   → 침묵 로그 수집
3. 침묵 빈도순으로 맵 보강 → 2로 돌아감
4. 게이트 1 · 2 통과   → 비로소 밸런스 측정 가능
5. 학습 freeze + 대표본 → 승률 산출 (게이트 3 · 4)
```

3 → 2 의 반복이 맵 작성의 주 루프다. 어디를 채울지 사람이 감으로 정하지 않고 **데이터가 정해 준다.**

## 6. 아직 정하지 않은 것

- 「의사결정 지점」의 단위 — 한 수마다인가, 한 우선권마다인가. 엔진 착수 때 정한다
- 침묵률을 라운드별 · 단계별로도 나눌지 (전투 단계 침묵과 진행 단계 침묵의 무게가 다를 수 있다)
- 맵이 후보를 좁혔지만 **틀리게** 좁힌 경우(정답이 후보 밖) 를 어떻게 잡을지 —
  침묵률로는 안 잡힌다. 공통 탐색을 전체 합법수로도 돌려 비교하는 방식이 후보다
