# 완성 점검 — `docs/완성_기준.md` 일곱 항목의 실제 명령과 출력

`docs/완성_기준.md` 7번 항목("점검 기록")이 요구하는 자리다. 항목이나 덱 하나를 끝낼 때마다
그 항목의 실제 명령과 출력 요약을 덧붙인다. 추측·"될 것이다"는 기록하지 않는다 — 돌려 본
결과만 적는다.

## 1. 호박옥 맵 이식 완료 — 통과 (2026-10-25, 30회차)

확인 방법(`docs/완성_기준.md` 1번): `maps/호박옥_봉인의_계약.yaml` 의 노드 id 집합이 `.md`
3~7장에 대응하는 노드를 전부 갖는가.

```
$ python3 -c "
from engine.mapfilter import 맵_읽기, 맵_검증
m = 맵_읽기('maps/호박옥_봉인의_계약.yaml')
v = 맵_검증(m)
print('노드 id 집합:', [n.id for n in m.노드들])
print('검증.깨끗한가:', v.깨끗한가)
print('검증.글로():', v.글로())
"
노드 id 집합: ['A', 'B', 'C', 'D', 'E', 'F']
검증.깨끗한가: True
검증.글로(): 문제 없음
```

대응 — A(3장 세금 미납 방지, 26회차) · B·C(4장 경합, 27회차) · D(5장 피니시 전환 게이트,
28회차) · E(6장 침전 제약, 29회차) · F(7장 상대 덱별 분기, 30회차). `.md` 3~7장 전부에
대응 노드가 있다(침전·상대 덱별 분기 포함) — 통과 조건 그대로 만족.

보충 — `python tests/test_filter.py` 44개 전부 통과(30회차 기준), `python
scripts/demo_호박옥.py` 정상 작동(평가 불가·보류 없음, 다만 이것은 4·5·6번 항목의 몫이라
여기서는 1번 통과의 부수 확인으로만 적는다 — 4·5·6번 자체는 합법수 생성 엔진이 아직 없어
별도로 통과 전이다).

F 노드는 7장이 "심리 층이 붙을 자리"(어느 수를 거를지가 아니라 어느 판단이 상대 정보를
요구하는지 표시하는 경계 문서)라서 금지·후보 없이 `참고`로만 채웠다 — 1층 필터가 거를
간선이 없는 것은 결함이 아니라 7장 자체의 성질이다(진행.md 30회차 기록 참조).

## 2. 던전마스터 맵 이식 완료 — 통과 (2026-10-25, 35회차)

확인 방법(`docs/완성_기준.md` 2번): `maps/던전마스터_셔플.yaml` 의 노드 id 집합이 `.md`
1~8장 대응 노드를 전부 갖는가(Y노드·미러는 미해결로 보류, 이유는 파일 주석).

```
$ python3 -I ...  # engine.mapfilter.맵_읽기 / 맵_검증 직접 호출 (scripts/맵검증.py는 3번 항목)
노드 id 집합: ['W', 'X', 'Z', 'D', 'F']
검증.깨끗한가: True
검증.글로(): 문제 없음
```

대응 — W(3장 보드 락 선점, 31회차) · X(4장 스킬 3효과 배분, 32회차) · Z(5장 교환 억제,
33회차) · D(7장 피니시 가설, 34회차) · F(8장 상대 덱별 분기, 35회차). `.md` 3~8장 전부에
대응 노드가 있다. Y(6장)는 `.md` 자체에 절이 없다(§6① 확인 필요가 안 풀려 보류 —
YAML 머리 주석에 이유 기록, 던전마스터 미러도 같은 이유로 보류) — 통과 조건이 명시적으로
허용하는 예외 그대로다.

보충 — `python tests/test_filter.py` 63개 전부 통과(35회차 기준, 호박옥 F 노드와 같은
"간선 없음·평가불가 없음·보류 없음" 테스트를 던전마스터 F 노드에도 추가). F 노드는 호박옥
F와 같은 이유로 `공통: false`·`간선: []`다 — 8장이 "이 판단은 상대 덱에 따라 갈린다"는
사실 자체를 표시하는 경계 문서라 금지·후보가 없다(진행.md 35회차 기록 참조).

## 3. 두 맵 모두 검증 깨끗 — 통과 (2026-10-25, 36회차)

확인 방법(`docs/완성_기준.md` 3번): `python scripts/맵검증.py` (새로 만듦). 두 맵 모두
`검증.깨끗한가 == True` 이고 `서술형불변식`·`자원미선언` 도 0건인가.

```
$ python3 -I scripts/맵검증.py
=== 호박옥_봉인의_계약.yaml ===
노드 id 집합: ['A', 'B', 'C', 'D', 'E', 'F']
검증.깨끗한가: True
서술형불변식: []
자원미선언: []
검증.글로():
문제 없음
→ 완성 기준 3번 통과: True

=== 던전마스터_셔플.yaml ===
노드 id 집합: ['W', 'X', 'Z', 'D', 'F']
검증.깨끗한가: True
서술형불변식: []
자원미선언: []
검증.글로():
문제 없음
→ 완성 기준 3번 통과: True

전체 결과: 통과
EXIT=0
```

기존 회차들이 `engine.mapfilter.맵_검증()` 을 파이썬에서 직접 호출해 두 맵이 이미
검증 깨끗임을 확인해 왔었다(29·31~35회차 기록) — 이번 회차는 그 확인을 `scripts/맵검증.py`
로 스크립트화해서 3번 항목이 요구하는 "명령 출력" 형태로 고정한 것이고, 결과 자체는
바뀌지 않았다. `깨끗한가` 프로퍼티는 `서술형불변식`·`자원미선언` 을 보지 않으므로
스크립트가 이 둘을 따로 검사해 종료 코드(0/1)에 반영한다. 테스트 1개 추가
(`test_스크립트_맵검증_두_맵_모두_통과` — 스크립트 모듈을 직접 로드해 `메인() == 0`
을 확인), `python tests/test_filter.py` **64개 전부 통과.** 호박옥 데모 회귀 없음.

## 4. 합법수 생성 동작 — 통과 (2026-10-27, 80회차)

확인 방법(`docs/완성_기준.md` 4번, 엄격 해석): `engine.legalmoves.커버하지_않음` 이 빈
tuple인가.

```
$ python3 -c "from engine.legalmoves import 커버하지_않음; print(len(커버하지_않음))"
0
```

**통과.** 2026-10-26 사용자가 엄격 해석을 확정하고 두 벽(① 발동 조건 표현 언어 확장 ②
세금차감 분할 납부 표기 신설)을 허가한 뒤, 48회차가 ②를 끝냈고 ①은 49~54회차(두 덱
14종·[신속]·[트리거]·[지속] 범위, 17개 효과)와 2026-10-27 사용자가 [소환]·[유언] 키워드를
추가로 허가한 뒤 78회차(조건 없는 12개)·79회차(비용 붙은 4개)·**80회차(횟수 상한 2개 —
마르모르·카르분쿨루스 3번[소환])**가 차례로 끝내, 범위의 18개 효과 전부가 채워졌다.
강제 발동(다크 엠퍼러·헬·컨트롤러의 [유언] 3번, 녹스 솜니페르 4번)은 사용자 결정
2026-10-27이 "애초에 `가용수단` 대상이 아니다"로 확정해 둬 `커버하지_않음`에서 세지 않는다
(허가를 넓혀도 이 결론은 바뀌지 않는다). 데모 두 개(`demo_호박옥.py`·`demo_던전마스터.py`)
모두 수동 입력 없이 돈다(43·45회차 이후 유지). 자세한 경과는 `engine/legalmoves.py` 모듈
docstring 46~80회차 항목, `cards/발동조건/<덱>.yaml` 각 파일 머리 주석,
`진행.md` 「반복 기록」 78~80회차 항목 참조.


## 5. 필터가 묶이지 않는 자리 없음 — 통과 (2026-10-26, 55회차)

확인 방법(`docs/완성_기준.md` 5번): 위 데모(`demo_호박옥.py`·`demo_던전마스터.py`) 출력에
「평가 불가」·「보류」가 몇 건 있는가. 4번이 아직 미통과라도 「평가 불가」·「보류」는
`engine/mapfilter.py`(1층 필터)가 맵의 `조건`·`후보`·`금지`를 대조하다 술어를 못 풀 때만
나오는 별도 신호다(`engine.legalmoves.커버하지_않음` 과 다른 층) — 그래서 4번과 독립으로
판정할 수 있다.

```
$ python3 scripts/demo_호박옥.py 2>&1 | grep -c "평가 불가\|보류"
0
$ python3 scripts/demo_던전마스터.py 2>&1 | grep -c "평가 불가\|보류"
0
```

두 데모 모두 0건 — 통과. (호박옥 데모 5개 국면·던전마스터 데모 6개 국면 전부 확인.)

## 6. 테스트 — 통과 (2026-10-26, 55회차)

확인 방법(`docs/완성_기준.md` 6번): `python tests/test_filter.py` 전부 통과 + 60개 이상 +
합법수 생성·던전마스터 맵·두 맵 교차 테스트 포함.

```
$ python3 tests/test_filter.py
...
188 passed, 0 failed
```

`188 ≥ 60`. 포함 여부 — 합법수 생성 테스트 **115개**(`test_합법수_*`, 다섯 동작 전부:
소환·발동·세금차감·표시변경·공격선언), 던전마스터 맵 테스트 **23개**(`test_*던전마스터*`,
W·X·Z·D·F 노드 + 평가불가/보류 없음 확인), 두 맵 교차 테스트 1개
(`test_스크립트_맵검증_두_맵_모두_통과`) — 전부 존재. **통과.**

54회차까지의 기록은 "6번 전체는 4번이 끝나야 완결된다"고 적어 뒀었다 — 그런데 6번의
확인 방법·통과 조건(`docs/완성_기준.md` 표)은 "테스트 스위트가 전부 통과하고 세 종류
테스트를 포함하는가"를 기계적으로 묻는 것이고, "합법수 생성의 모든 동작에 테스트가
있는가"(4번이 끝나야만 가능한 것)를 묻지 않는다 — 두 질문을 섞어 4번에 종속시킨 것이
55회차가 발견한 과잉 해석이었다. 표의 글자 그대로, 명령 출력으로 확인한 결과를 그대로
적는다 — 추측이 아니라 55회차가 직접 돌려 본 값이다.

## 7. 점검 기록 — 이 문서 자체 (2026-10-26, 55회차)

확인 방법(`docs/완성_기준.md` 7번): 1~6번의 **실제 명령과 출력 요약**이 이 문서에 적혀
있는가(추측·"될 것이다"는 불인정). 위 1~6번 전부 실제 명령 출력으로 적혀 있다. **이 문서
자체는 통과** — **2026-10-27, 80회차가 4번을 마저 닫아 일곱 항목 전체가 참이 됐다**
(`docs/완성_기준.md` 표 1~7번 전부 ✅). 다음 우선순위는 `docs/완성_기준_듀얼.md`의
